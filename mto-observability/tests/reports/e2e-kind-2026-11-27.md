## Not driven live, and why that is honest

`WorkqueueBacklog`, `WebhookErrors`, `WebhookLatencyHigh` and the non-finops
`ReconcileErrors` twins have no clean external forcing function on a healthy
lab: you cannot make a live controller stop draining its queue, or make an
admission webhook return 5xx, without killing the pod that reports the metric.
Their logic is pinned by the promtool unit layer (every one of the 24 rules
fires and resolves on synthetic series in `tests/unit/rules.test.yaml`); this
layer proves the pipeline those rules evaluate in — monitors → authenticated
scrape → rules → ALERTS — which the nine lifecycles above exercise fully.

## Findings (each actioned)

1. **CronJob `suspend:` is not a pause button**: the finops operator's
   `CreateOrUpdate` reverts `spec.suspend` on its next reconcile, so the
   original staleness scenario silently kept succeeding — `MTOCostDataStale`
   was *correctly* quiet. Scenario rewritten to an OpenCost outage (the true
   eu-1 shape); upstream behavior noted on the operator tickets.
2. **SubscriptionChargeCollection never records execution status** — Jobs
   complete green while the CostJob status stays empty forever (22h observed),
   so `MTOCostJobNeverSucceeded` fires permanently on healthy installs:
   the alert honoring its contract against a real upstream gap. Filed +
   fixed upstream (finops-operator PR #111); live re-verification here once
   the lab image rebuilds from a release carrying it.
3. **Harness**: the summary's failure count missed tagged FAIL lines on the
   first run (reported 0 with 1 failure) — fixed; counts now match the lines.
