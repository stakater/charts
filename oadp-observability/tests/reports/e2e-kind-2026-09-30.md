## Note

This run adds **per-schedule budgets**: the baseline schedule is annotated with a 3-minute budget
while the chart default is 6 minutes. `oadp:schedule_budget_seconds` resolved to 180 for it and
`OadpBackupStale` fired inside a 300-second deadline, which the 6-minute default could not have
met. The one ❌ is a test race: the value check for the freshly created unannotated schedule ran
before its first scrape and rule evaluation (about 30 seconds). Queried a minute later on the same
cluster it read 360, and the alert that depends on it fired as expected. `expect_value` now polls.
